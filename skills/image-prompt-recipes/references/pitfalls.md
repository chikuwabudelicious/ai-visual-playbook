# 実際に起きた失敗と対処（画像）

1項目＝症状 → 原因 → 対処。

## 文字・数字

- **数字が勝手に変わる**（「500」が「560」に） → モデルは数字を見た目で補う → 末尾に `Numbers must be exactly: …` を列挙。生成後に原稿と照合。
- **頼んでいない題・看板の字が足される** → 「図」「町」と言うと、題や店の看板を描きたがる → `no overall title` と `do NOT add any other words, signs, shop signs, banners, captions` を毎回。
- **根拠の無い比率が描かれる**（棒グラフの高さ・円グラフの割合） → 見栄えのために具体値を置いてしまう → 原稿に無い比率は「等量で描く」と指示する。棒の高さも数字のうち。
- **ラベルが長いと崩れる・勝手に要約される** → 1ラベルに入る字数には限りがある → 12字（欧文4語）まで。`Keep each label SHORT exactly as given.`
- **ベトナム語の声調記号が抜ける・重なる** → `correct diacritics` を指定。必ず目視。
- **タイ語が別の文字に化ける** → 生成前に1枚だけ試す。だめなら方式A（文字は自分で置く）に切り替える。
- **`CO2` がそのまま描かれる** → 下付き文字は Unicode（`CO₂`）で渡す。

## 画風・構図

- **小さな図の周りに大きな余白** → `The diagram must FILL the canvas … keep a clean 4% margin`。それでも残る余白は生成後にトリム（地の色を基準に切る）。
- **同じ資料の図の画風がばらつく** → 画風の頭文を毎回同じ文字列で使う。1文でも変えると別の絵柄になる。部品が多いなら12個を1枚に描かせて切り分ける。
- **特定の国風の家並みが出る**（瓦屋根・教会の尖塔・桜など） → 「特定の国に見せない」と抽象的に言うだけでは止まらない → 出てほしくないものを具体的に列挙して禁止する。
- **伝統模様が全面に出て土産物っぽくなる** → 「隅の薄い飾りだけ」と範囲を限る。
- **速いモデルで道が途切れる・アイコンの線が欠ける** → 下書きは速いモデル、本番は細密なモデル。俯瞰図は `Roads must connect continuously` を足す。
- **帯（横長の風景）の上端が切り口として目立つ** → 上部を「平らな単色・雲もグラデーションもなし」と言い切り、生成後に上端をぼかして透過にする。
- **画像編集で絵柄が写実寄りに変わる** → モデルによって編集の癖が違う → 文字の差し替え・部分修正には、画風を保つモデルを1つ決めて固定する。

## 写真風

- **人の顔がはっきり写る** → `no people's faces in focus`、背景の人は「小さく・ぼかす・特定できない」。
- **生成写真を実績のように使ってしまう** → 生成した情景は説明用。現地の記録・導入実績として出さない。
- **画像の上の文字が読めない** → 写真に文字を載せる前に暗幕（下から上へのグラデーション）を敷く。

## 道具・運用

- **モデル名を推測して 404** → 「2.5」「3」など、それらしい名前でも存在しないことがある → 使う前に API のモデル一覧で確かめる。新しい名前が出ていないかも一覧で見る。
- **使えるはずのモデルで 403** → 組織の認証が要るモデルがある → 逃げ先（次に良いモデル）を決めておき、403/404 のときだけ落とす。
- **透過指定でエラー** → 透過に対応しないモデルがある → 白地で描いてから抜く。
- **社内の通信監視ソフトで HTTPS が証明書エラー** → Python は OS の証明書ストアを使う設定（`truststore`）にする。
- **画像サービスが規約で拒否（403 "terms of use"）** → 同じ画像でも経路（クラウド経由・APIキー経由）で判定が違うことがあった → 別の経路で試す。叩き続けない。
- **大量に作ってから全部やり直し** → 量産の前に1枚だけ作り、目で確かめてから残りを回す。費用は事前に見積もる。
