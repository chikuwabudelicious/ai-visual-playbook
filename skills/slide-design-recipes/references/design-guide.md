# スライドの規範と罠

## 見せ方の約束

- **1スライド1メッセージ。** 図が2つ要るなら2枚に割る。
- 結論は図の下に1行の帯で書く。読み手に要約を任せない。
- 説明文は2行まで。3行要るなら情報を削るか、面を割る。
- 色は意味に結びつける（緑＝解決、琥珀＝強調、テラコッタ＝課題・減らすもの、ティール＝水）。面ごとに色を発明しない。主役の色は1枚に4色まで。
- 静止画で「動き」を感じさせる手段は3つだけ：方向のある図形（シェブロン・矢印）、数字の大小の落差、色の対比（課題色→解決色）。
- 影は情報の階層（カード＝浮く／下地＝沈む）にだけ使う。飾りのグラデーション・斜め罫は使わない。
- 英数字だけ別の書体にしない。混植すると行間が崩れる。
- 写真の上に文字を載せるときは暗幕（グラデーション）を敷く。

## 罠（症状 → 原因 → 対処）

- **PowerPoint で開けない／修復を求められる** → 図形の `effectLst` が二重に付いた（影を付けるライブラリと手書きの XML が重なる） → 影は付けないか1か所で付ける。`deck.py` は保存後に検査する。
- **幅や高さが0以下の図形で開けない** → 計算で負の寸法ができた → 図形を置く前に寸法を正に丸める。
- **タイ語が全部ラテン文字に化ける** → OOXML はタイ文字を complex script として `a:cs` の書体で描く。`latin` と `ea` しか指定していなかった → 文字ごとに latin・ea・cs の3系統を指定する（`deck.py` は `font_cs`）。
- **ベトナム語・タイ語の字が出ない** → 和文の UD ゴシック系にはその字形が無い → タイ語は Leelawadee UI、ベトナム語・ルーマニア語は Segoe UI、ゾンカ語は Microsoft Himalaya など、その言語の字がある書体にする。
- **記号（✉ など）だけ細い別書体で出る** → 書体にその字が無く、OS が代わりの書体で描いた。目視では気づきにくい → 使う記号は fontTools の cmap で有無を確かめる。無ければ文字で書く（「メール：」）。
- **英語版で見出しが罫線にかかる** → 文字幅を全角1・半角0.55で見積もると、欧文は2割ほど甘い → 欧文だけの見出しは見積もりに 0.82〜0.90 の余裕係数を掛ける。
- **和文が既定の書体（游ゴシック等）になる** → `latin` だけ指定して `ea` を書いていない → 3系統とも指定する。
- **図の数字が原稿と違う** → 生成画像の焼き込み文字の誤り → 図の数字は原稿と1つずつ照合する。変わる数字は図形で描く（画像に焼かない）。
- **PowerShell スクリプトの日本語が化ける**（Windows） → BOM の無い UTF-8 の `.ps1` は Windows PowerShell 5.1 が ANSI として読む → UTF-8（BOM 付き）で保存する。

## 面の配置の目安（横A4・11.69×8.27 inch）

- 左右の余白 0.75 inch。帯の高さ＝幅/12（約0.97 inch）。本文は帯より上で終える。
- 文字の大きさの目安：題 30pt、見出し 15〜18pt、本文 12〜14pt、注記 9〜10pt。
- 数字の面は数字を 40pt 以上に、補足は小さく（落差で読ませる）。
