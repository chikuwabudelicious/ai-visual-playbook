# コピペ用プロンプト集

Claude Code・Codex にそのまま貼れる依頼文と、中で使う生成AI（映像・画像・BGM・声）への指示の型。
`＜ ＞` を埋めて使う。埋めない項目は型の既定値で進む。例の題材はすべて架空。

## 0. 共通ブリーフ（どの型でも最初に埋める）

```
動画を作って。video-format-recipes の型 ＜F01〜F35＞ で。
- 目的：＜例：駅前の自転車シェアを知ってもらう＞
- 視聴者：＜例：通勤で駅を使う20〜40代＞
- 置き場所：＜例：Instagram Reels と YouTube Shorts＞
- 比率・尺：＜例：9:16・24秒＞（既定：型の標準）
- 音：＜ナレーション／BGMのみ／無音＞（既定：型の標準）
- 原本：＜数字・文言の出どころのファイル。例：docs/facts.md＞
- 禁止：＜例：料金は出さない／他社名を出さない＞
- 素材：手元の素材 ＜フォルダ＞ を先に使う。新しく生成が要るなら、作る前に何を何本・費用の目安を聞いて
数字は原本にあるものだけ。無いものは「◯◯（要確認）」にして最後にまとめて。
1本目はテンプレート＋データ1件で作り、静止画で見せてから書き出して。公開・投稿はしないで。
```

**よくある失敗と直し方**

| 書き方 | 起きること | こう書く |
|---|---|---|
| 「かっこいい動画を作って」 | 型・尺・媒体が毎回ぶれる | 型の ID と置き場所を書く |
| 「数字を入れて説得力を」 | 原本に無い数字・比率が描かれる | 「原本は＜ファイル＞。無い数字は要確認に」 |
| 「6本まとめて作って」（1本目の確認なし） | 同じ不具合が6本に入る | 「1本目を静止画で見せてから残りを」 |
| 「ナレーションに合わせて」 | 手で秒を打ち、録り直しでずれる | 「尺は1文ずつの音声の実測から機械で」 |
| 「ここもあそこも直して」 | 直し漏れ・頼んでいない所まで変わる | 「1回に1点。それ以外の要素と書き出し設定は変えない」 |
| 「いい感じのBGMで」 | 前奏・ブレイク入りで拍に乗らない | テンポ・楽器・構成・尺を書く（§2-5） |

## 1. 型ごとの依頼文

### 台本・カット表だけ先に作らせる（どの型でも）
```
型 ＜F12＞ の拍の表を写して、＜題材＞ のカット表を作って。列は「区間・拍・秒・画面の文字・画（素材）・動き・音」。
画面の文字は型の字数の目安に収め、超える行には印を付けて。素材の欄は「手元にある／コードで描く／生成が要る」のどれかを書き、
生成が要る行にはプロンプト案（英語）を添えて。数字の行には原本の場所を書いて。まだ書き出さないで。
```

### F01 無音Q&Aショート
```
F01 の型で、＜テーマ：例 家庭の古紙回収＞の1問1答を＜6＞話作って。原本は＜ファイル＞。
よくある疑問を＜6＞個選び、episodes/ep01〜06.json（問い3行・ふつうは・答え・図の種類・理由3つ・決め2行・次回予告。理由の改行は /）を書いて。
JSON を見せて OK をもらってから全話を書き出し、1秒おきの一覧画像で確認して。
```

### F02 展示会ループ
```
＜展示会名＞のブースで流すループ動画を作って。モニターは＜横 1920×1080＞、音なし、40秒で5枚を循環。
1.組織名と一言 2.課題 3.しくみの図 4.実績の数字（原本＜ファイル＞） 5.連絡先とQR。
会場の3m先から読める大きさ（画面の高さの1/12以上）で。最後の色を最初と同じにして継ぎ目を消して。
```

### F03 モノ視点ストーリー
```
「＜回収されたペットボトル＞」が主人公の物語動画を作って。一人称の語り、＜75＞秒、＜16:9＞。
7拍（誕生→使われる→捨てられる→転機→変身→次の役目→最初の場所に戻る）。
場面の静止画は画風固定文で作り、映像生成で4〜8秒ずつ動かして（文字なし）。工程の内部は図解で。
台本とカット表（ショット番号・カメラ・動作・場所と光・プロンプト案）を先に見せて。生成映像を実在の施設とは言わない。
```

### F04 Before / After
```
「＜手で仕分ける今のやり方＞」と「＜回収箱を色分けしたやり方＞」を比べる動画を、F04 の静かな版（1:1・24秒・BGMのみ）で作って。
観点は＜時間・手間・まちがい・費用＞の4行。各セルは2行まで。数字は原本＜ファイル＞にあるものだけ、無ければ言葉で。
```

### F05 数字1つ
```
「＜年間 約3万冊＞」を1本15秒で刺す動画を、templates/number の型で作って。9:16、BGMのみ。
前振り2行→カウントアップ→比べる棒（原本にある比だけ。無ければ棒なし）→意味づけ2つ→発信者名と出典。
```

### F06 用語ミニ解説
```
＜用語集のファイル＞から＜3＞語を、1語60秒の解説動画にして。
構成：一言定義→身近なたとえ→図で仕組み→私たちの活動との関係→まとめ。ナレーションは1文ずつ合成して照合。
台本を先に見せて。制度の説明は原本の言い方から外れないこと（約束・断定にしない）。
```

### F07 手順・研修
```
＜機器名＞の操作手順の研修動画を作って。原本は＜手順書のファイル＞（無ければ作らずに止まって）。
章ごとに30〜60秒（準備・開始・作業・確認・片付け・異常時）、各章「目的→番号つき手順→注意→確認」。
字幕は＜言語＞。撮影素材＜フォルダ＞があれば無音・言い直しを詰めて使い、無ければ図解で。
```

### F08 イベント告知
```
＜読書会 第3回＞の告知を 9:16・15秒で作って。テーマ＜＞・日時＜＞・場所＜＞・申込方法＜＞を4拍で。BGMの拍で切り替え、最後にQRを2秒止める。
```

### F12 1枚の図を動かす
```
F12 の型で、＜図のファイル＞を「図で見る」の＜#04＞にして。
図を開いて、寄る場所3か所（図の中の割合 x0,y0,x1,y1）・名前・説明2行・最初の一言・引いて一言を figures/f04.json に書き、先に見せて。
説明の文言と数字は原本＜ファイル＞にあるものだけ。図に焼き込まれた数字・言い回しも原本と照合し、食い違えば使わずに報告して。
```

### F13 会場参加型クイズ
```
F13 の型で、＜勉強会 第N回＞の締めクイズを3問、＜日本語＞で作って。原本は＜その回の資料＞だけ。
下の「クイズ3問」の指示で sessions/sNN_q1〜q3.json を書き、先に JSON を見せて。
OK が出たら1問ずつ書き出し → 連結・音 → QA。つなぎ目と最終フレームの画像も見せて。会場に通訳が＜入る／入らない＞。
```

### F14 対談チャット型ショート
```
F14 の型で、＜記事ファイル＞を対談の1話にして。下の「記事→対談台本」の指示で episodes/＜id＞.json を作り、src 欄（記事の行）つきで先に見せて。
OK が出たら声だけ先に作って尺（会話45〜58秒・全体59.5秒以下）と照合結果を見せ、0・15・30・45秒の静止画を見せてから書き出して。
```

### F21 データストーリー
```
F21 の型で、データストーリーを1本作って。題材＜例：まちの資源回収量＞、原本＜ファイル＞（数字はここからだけ）。
下の「数字の選び方」の指示で 問い→そして→しかし→だから を4〜6枚。書き出し前に、各カードの数字が出そろった時刻の静止画を見せて。
戻りに、画面に出る数字ごとの「原本ファイル:行」と出典の表を付けて。
```

### F22 ポッドキャスト＋オーディオグラム
```
F22 の型で、＜記事ファイル＞を2人の音声番組の1話にして。下の「記事→長尺の対談台本」の指示で台本を作り、src 欄つきで先に見せて。
OK が出たら音声だけ作って、尺と書き起こしの照合結果（「聞こえた」を全行）を報告 → 動画2本を書き出し → 一覧画像を見て報告。配信はしないで。
```

### F23 ニュース番組型の定期便
```
F23 の型で、＜番組名＞の＜YYYY年M月号＞を作って。原本は＜月次の報告書＞だけ。下の「月次報告→号の JSON」の指示で下書きして先に見せて。
戻りに、読み上げ・画面の事実ごとの「原本ファイル:行」を付けて。送付はしないで。
```

### F24 切り抜き工場
```
F24 の型で、＜完成動画.mp4＞と＜字幕.srt＞から縦の切り抜きを＜2＞本作って。
まず字幕から 20〜45秒・章をまたがない区間の候補を点数つきで一覧にし、下の「字幕からの区間選び」に従って選んだ理由を書いて見せて。
画面に焼き込まれた文字（図のカード・テロップ）もコマで見て、禁止事項に当たる区間は替えるかぼかす。新しい映像・音声は足さない。
```

### F25 実写の1カット
```
F25 の型で、＜実写フォルダ＞から＜4＞話作って。1話＝区間1つ＋事実1つ（原本＜ファイル＞から）。
下の「映像と事実の対応」に従って、区間ごとに 0.4秒おきのコマを見てから in/out・切り出し枠・ぼかしを決めて。声は1〜2文。
```

### F26 選べる動画
```
F26 の型で、＜題材：例 駅前の自転車シェア＞の選べる動画を作って。
立場は＜3つ：利用者の方／近くのお店の方／行政の方＞、各立場の問いは3つ＋共通の「しくみ」「次の一歩」。
声は＜過去に承認した1文音声の一覧ファイル＞の文 id を並べて答えにする。足りない答えは作らずに「無い問い」として報告。
「このケースでは」「ここでも」など前後の話を指す文は使わない。まず問いと文 id の表を見せて。
```

### F28 仕分けゲーム
```
F28 の型で、＜カフェの分別箱＞の仕分けゲームを1話作って。入れる物・入れない物を合わせて5つ（入れない物を2つ）。

品物の絵は「絵の一式」の指示で1枚に12個描いて切り分ける。描く前に品物の一覧を見せて。
```

### F29 架空の町の地図
```
F29 の型で、＜古着の行き先＞を1話作って。架空の町の地図（実在の地名は使わない）に場所を3〜6つ、道を4本（出発,到着,g＝回す／r＝捨てる）。
各道に見出しと説明2行。文言は原本＜ファイル＞の言い回しだけ。赤い道を前半、緑の道を後半に。

### F30 4コマ

F30 の型で、＜図書館の返却ポスト＞の疑問を4コマ（起・承・転・結）にして1話作って。
登場人物は＜利用者（驚き役）・司書（答える人）＞。吹き出しは3行まで、1行10字前後。驚き役の誤解は次のコマで必ず直す。

### F31 紙芝居
```
F31 の型で、＜牛乳パックのパックン＞が主人公の紙芝居を1話作って。場面は10枚前後、1枚＝1〜3文、子どもに分かる言葉で。

F33 の型で、＜説明会・日付＞のあとに送る宛名入り動画を作って。宛先は＜一覧ファイル＞。1件ずつ recipients.csv に1行。

## 2. 中で使う生成AIへの指示の型

### 2-1. 映像（Veo などの画像→動画）

書く順は **[カメラ] → [被写体] → [動き] → [場所・光] → [画風]**。英語で書く。

```
＜カメラ：Slow dolly-in, eye level＞. ＜被写体：A paper coffee cup on a wooden counter＞.
＜動き：one simple action — steam rises gently from the cup＞. ＜場所・光：a small neighborhood cafe, soft morning window light＞.
＜画風：cinematic, shallow depth of field, warm natural color＞.
No text, no letters, no logos, no signage, no close-up faces.
```

- **1ショット＝カメラ1・動作1・照明1。** 8秒1本より4秒2本をつなぐほうが崩れにくい。尺と画面サイズはプロンプトではなく API の引数で
- **元の絵に写っているものを動かす指示にする。** 絵に無い人や物を足すと構図が崩れる。外見は書き直さず、動きだけ書く
- 否定形より「あってほしい状態」を書く。色は3〜5色を名指し
- 失敗したら「カメラを固定 → 動作を減らす → 背景を整理」の順に単純化する
- 得意：ゆっくりしたドリー・パン、風・水・雲・湯気・人の自然な動作、模型の周りをゆっくり回り込む。苦手：4人以上の群衆、物の受け渡しの連続、手元の細かい作業
- 生成物の音は捨てる（`-an`）。環境音を活かすなら、語りと重ならない場面だけ
- セリフは引用符、効果音は `SFX:`、環境音は `Ambient noise:`。1回で複数カットなら時刻で区切る：`[00:00-00:02] Medium shot ... [00:02-00:04] Reverse shot ...`
- **参照画像は役割を宣言する**：`Using the provided images for the barista and the cafe, create a medium shot of ...`（外見は書き直さず、関係と動作だけ）。
  動画を参照に渡すなら `video 1 is for camera movement only; do not copy its subject`
- 「カメラ固定」は `Static camera; the framing never changes.` と書く（"tripod" と書くと三脚が映ることがある）

**変身カット（模型→実写、昼→夜など）は補間に任せない**：
```
1) 2枚の静止画を同じ構図で用意する（2枚目は1枚目を画像編集で作ると構図が完全に一致する）
2) 1枚目は静止画のまま、2枚目は「Static camera; the framing never changes.」で4〜8秒の映像にする
3) 両方に同じゆっくりした寄り（8秒で3〜4%）を掛け、ffmpeg の xfade=smoothright:duration=1.6 でつなぐ
```

### 2-2. 人物・キャラクターを固定した物語

```
1) 主人公のキャラクターシート（正面・斜め・横・背面＋顔の寄り）を画像生成で4案。私が1つ選ぶまで先へ進まない。
2) 場所の資料（照明の既定・カメラ位置）→ 絵コンテ表（ショット番号・種別・カメラの動き・人物と動作・場所・照明・プロンプト案、1ショット4〜8秒）。
3) 基準になるショットを先に作り、その出力を後のショットの参照にする。カットをまたぐ動作は前のクリップの最終フレームを次の先頭に。
4) 同じ場所のショットは人物・環境・画風の文を一字一句同じにし、動作とカメラだけを変える（1ショット80〜150語）。
5) キーフレーム一覧（静止画）と概算費用を1枚にして私の承認を取ってから、映像を生成する。
```

### 2-3. 場面の静止画 — 画風固定文

```
＜場面の中身：A quiet public library reading room with tall windows＞. Style lock: soft cinematic photograph, warm natural light,
muted greens and amber, 35mm lens, shallow depth of field, clean composition with empty space ＜at the top / at the bottom＞ for captions.
No text, no words, no letters, no watermark, no logos.
```

- 同じシリーズは画風固定文を一字一句変えない。人物を出すなら同じ参照画像を毎回渡す
- 字幕を置く側に空きを作らせる（`empty space at the bottom for captions`）

### 2-4. 絵の一式（1枚に12個描いて切り分ける）

```
Flat vector illustration set, friendly, clean and modern, like a premium explainer video. Rounded shapes, consistent medium outline
in dark gray #2B3A31, soft flat shading. Palette: ＜3〜5色の色コード＞, plus natural colors where needed.
Exactly 12 separate items arranged in a neat grid of 4 columns by 3 rows on a plain PURE WHITE background (#FFFFFF), each item isolated
and centered in its own cell with generous empty white space around it; items must not touch or overlap.
No text, no letters, no numbers, no labels, no logos, no brand marks, no watermark, no frames or borders.
Row 1: (1) ＜a crushed aluminum can＞; (2) ＜a glass jar＞; ... Row 3: ... (12) ＜…＞.
```

- 1枚の中で描かせると線の太さ・色・角度がそろう（別々に頼むとばらつく）
- 人物は「行＝人・列＝表情」にし、`Keep each character identical across the four columns` を添える
- 切り分け：白地の塊を「4列×3行のマス」に割り当て、同じマスの塊をまとめる（割れたガラスのように1個が2つに分かれるため）。
  背景は「縁につながる白」だけを透明にする（皿や紙の白は残る）

### 2-5. BGM（音楽生成モデル）

```
＜ムード：Punchy, bright modern / Calm documentary＞ instrumental for ＜用途：a 24-second vertical social video with on-screen text＞.
Exactly ＜120＞ bpm, 4/4, ＜楽器：plucky marimba, round synth bass, claps on 2 and 4＞.
Structure: ＜starts on the downbeat with no fade-in / lift at 6s / final big hit at 20s＞.
About ＜30＞ seconds. Instrumental only: no vocals, no choir, no spoken words.
```

- 会場クイズ向けの例：`Bright, playful game-show style instrumental for a live audience quiz shown on a projector. Exactly 128 bpm, 4/4. The groove starts on the very first downbeat (no intro, no fade-in) and keeps the same energy all the way through so that any 16 bars can be looped: punchy kick on every beat, handclaps on 2 and 4, bouncy pizzicato strings and a marimba hook, plucky synth bass, light shaker. Cheerful, curious, friendly, not aggressive. No breakdown, no tempo change, no big ending. About 60 seconds long. Instrumental only: no vocals, no choir, no spoken words.`
- 会話の下に敷く例：`Calm, warm, unobtrusive lo-fi instrumental to sit under a spoken conversation in a 60-second vertical video. 76 bpm, soft felt piano chords, mellow Rhodes, light brushed drums, warm upright bass, faint vinyl texture. Even and steady from the first second to the end: no intro build, no drops, no big crescendos. Sparse arrangement leaving space in the mid frequencies for voices. About 70 seconds long. Instrumental only.`
- 用途・テンポ・楽器・「どこを切っても同じ勢い」・声の帯域を空ける、を書くと使える曲が来やすい
- **テンポは指定どおりにならない**（120指定→実測117.5、128指定→実測120）。必ず拍を解析してから出来事を置く（例：`librosa.beat.beat_track`、HyperFrames の `beats`）
- 「前奏なし・ブレイクなし」と書いても入ってくる。ループに使うなら拍の解析結果を見て、グルーヴの区間（小節の頭から8小節）だけを繰り返す
- 生成曲・手持ち曲とも、公開先での利用条件を確かめる

### 2-6. ナレーション（TTS）

- 台本は**1行1文**（2文を1行にすると二度読みが起きやすい）。読みが怪しい語は読みの辞書で固定（例：`{"御用達": "ごようたし"}`）、短い記号は言葉で（"Q1" → "Q one"）
- 話し方は台本形式の「指示の欄」にだけ書き、ト書きを台詞に入れない（読み上げられる）
- 生成後は必ず書き起こして照合する（`pitfalls.md` の声の節）

**説明調（Gemini TTS で効いた台本形式）**
```
# AUDIO PROFILE: Narrator
## THE SCENE: A calm explainer video about ＜topic＞, read by a single narrator.
### DIRECTOR'S NOTES
Style: a calm, clear professional narrator. Warm, trustworthy, plain-spoken. Not dramatic, no exaggerated emotion.
Pace: natural professional pace; short pauses only at commas and periods.
Accent: standard Tokyo Japanese.
#### TRANSCRIPT
＜1文＞
```

**ニュースのアナウンス調（F23）**：Style を `a calm, clear Japanese TV news anchor reading a short monthly news bulletin. Crisp announcer diction, confident, neutral and trustworthy.`、
Pace を `brisk, steady professional newsreader pace` に。英語は `international TV news anchor`・`Accent: neutral international English.`

**2人の声（F14・F22）**
- 1ターン＝1話者で合成する。吹き出し・字幕の時刻を声の頭に正確に合わせられ、直した1行だけ作り直せる（弱点はターンをまたぐ抑揚）
- 聞き手：`a curious, friendly interviewer asking the writer of an essay a genuine question in a relaxed conversation. Light and natural, a little skeptical, never exaggerated.`
- 筆者：`a calm, thoughtful essay writer answering an interviewer in a relaxed conversation. Sincere and plain-spoken, gently confident, not lecturing, not dramatic.`
- 声は高さと調子がはっきり分かれる組み合わせに（例：低く落ち着いた男性声＋軽やかな女性声）
- 抑揚を優先するなら1リクエストで2話者（API が対応していれば）。そのとき字幕の時刻は単語の時刻からの推定になる

**読み聞かせ（F31）**：Style に `a gentle storyteller reading a picture-story show to young children; lines in quotes are read a little more playfully`。

### 2-7. 台本・問題を作らせる指示

**クイズ3問（F13）**
```
＜会の名前＞第＜N＞回の締めに会場で流すクイズを3問つくる。原本は＜その回の資料＞だけ。原本に無い数字・事実は作らない。
各問：question（日本語1行17字×2行まで）、choice_a〜c、answer、answer_big、reason（1〜2行）、note（「ここに注意」1行）、source（原本のファイル:行）。
- 3つの選択肢はほぼ同じ長さ（正解だけ長い・理由つき、にしない）
- 誤答の数字は正解の桁違い（1/10倍・10倍）だけ。同じ回の資料に出る別の数字と同じ数にしない。誤答の数字は承認を取る
- 誤答でも、写真で切り取られたら誤解を生む文言（約束・費用負担・実施の断定と読めるもの）は使わない。冗談に見える誤答も使わない
- 確約・誇大表現（必ず・ゼロ・100%・業界初）を使わない
```

**記事→対談台本（F14）**
```
＜記事.md＞を読み、聞き手（q）と筆者（a）の台本 JSON を作る。
- 交互に6〜7往復。最初は聞き手の問い、最後は筆者の結論
- 聞き手は読者が抱きそうな前提・疑問・反論を言う。記事の中に反論として書かれている文があれば優先して使う
- 記事の中心主張を聞き手に言わせて筆者に退けさせない。筆者の但し書き（「〜だけでは足りない」）は限定の語を落とさず筆者が言う
- 列挙を短くするとき、後のターンの前振りになる項目は残す
- 筆者は記事の文をなるべくそのまま話し言葉に直すだけ。記事に無い主張・数字・固有名詞・事例を足さない
- 1ターンは句読点を除いて40字以内（聞き手25字以内）、全体で270〜290字。「/」で改行位置（1行13字目安）。マーカーは筆者の要の語に1〜4個
- 空句・誇張・感嘆符を使わない。各ターンの src に記事の行番号と元の文
```

**記事→長尺の対談台本（F22）**
```
＜記事.md＞を、2人の音声番組の台本 JSON にする。
- 20〜30ターン・声に出して3〜4分（日本語で約900〜1,100字）。1ターン目で番組名と記事の題を言い切る（10秒以内）、2〜3ターン目で「三つの区切りで聞いていきます」
- 区切りは3つ。ラベルは記事の小見出しをそのまま
- 聞き手の問いは記事本文に書いてある読者の疑問・反論から作る（記事の外から論点を持ち込まない）
- 筆者の答えは記事の文をほぼそのまま話し言葉に。記事に無い主張・数字・固有名詞・たとえ話を足さない
- clip に、いちばん良いやり取り（2〜4ターン・30〜45秒）と冒頭に出す1行の問い（14字以内）
```

**数字の選び方と出典表示（F21）**
```
原本＜ファイル＞から、問い→そして→しかし→だから の物語になる数字を4〜6個選ぶ。
- 原本にある数字・単位・年・出典名だけ。推計の数字は使わないか、注記に「推計」と書く
- 数字の表記は原本どおり（「約」も残す）。幅のある数字は value と value_to
- グラフの量は数字そのもの。原本に比率が無いものはグラフにせず、割合の残りに名前を付けない
- 注記は原本の文言の範囲で。対象を限定する語を落とさない、英訳で因果（so）を足さない
- 出典の帯は「機関名・年」＋詳細1行。年が発行年かデータの時点かを分かるように
- 締めは数字を出さず、言い過ぎない結論に。各カードの src に原本のファイル:行
```

**月次報告→号の JSON（F23）**
```
＜番組名＞の＜YYYY年M月号＞を下書きする。前号の JSON を写して、号・発行日・冒頭・次号予告を新しい号に。
- 原本（事実はここからだけ）：＜月次報告書＞、＜日程・名称の一覧＞
- ニュースは3本・1本＝読み上げ2〜3文（全体45〜60秒）。見出しは日本語20字・英語40字まで
- 金額・予算は出さない。資料間で食い違う事項・未記入の欄は使わない。予定には「（予定）」
- ティッカーは今後の予定3〜4件。各文・各表示に src（原本のファイル:行）
```

**字幕からの区間選び・見出し（F24）**
```
元動画の字幕（文と段落の一覧と候補）から、切り抜きにする区間を選ぶ。
- 1本で1つの要点が完結する区間（段落の頭で始まり段落の終わりで終わる・章をまたがない・20〜45秒）。文の途中で切らない
- 同点の候補なら、強い訴求点・締めの文まで入るほうを選び、理由を書く
- 画面に焼き込まれた文字（図のカード・ラベル）も見る
- 見出しはその区間の字幕にある言葉だけで、日本語15字・英語32字以内。新しい主張・数字を作らない。
  一部の働きを全体の手柄のように書かない
- 生成映像の人物・顔の大きさは見たとおりに書く（推測で「遠景」と書かない）
```

**映像と事実の対応・映り込みの確認（F25）**
```
実写の区間から、1話に区間1つ・事実1つを組む。
- 映っているものと事実がはっきり対応する区間を選ぶ。映っていないことを映っているように言わない。言い方で画面の中身を断定しすぎない
- 使う前に区間のコマを 0.4秒おき（短い区間）か 1・4・7秒で見る。包装の印刷・標示・ナンバープレート・名札・顔の寄り・白飛びの秒は
  in/out で外すか、切り出し枠の外に出すか、標示ごとの小さなぼかしで隠す。縦と正方形の両方の枠で主役が見えるか確かめる
- 止め絵は作らない。逆に流れても不自然でない絵は往復、落ちる物などは減速してぶれていないコマに着ける
- 各話に「見た内容と避けたもの」、src に原本の行
```
