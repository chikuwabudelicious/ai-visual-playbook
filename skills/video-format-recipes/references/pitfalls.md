# 実際に踏んだ罠と回避策

1項目＝**症状** → 原因 → 対処。モデル・道具の挙動は 2026-09〜11 時点の実測で、版が変わると変わることがある。
多くは「機械QAが全部合格したのに、画で見るとおかしい」型の不具合だった。検査を足すときの参考にする。

## 生成映像（Veo など）

**M1. 始点と終点の2枚を渡すと、途中の映像が崩れる**（別の場所に変わる・光が炎のように見える・最後の1秒で終点へ跳ぶ）
- 原因：2枚の違いが大きいと補間が破綻する。指示を絞っても直らない
- 対処：1枚目は静止画のまま、2枚目だけを「カメラ固定」で映像化し、両方に同じゆっくりした寄りを掛けて `xfade=smoothright` のワイプでつなぐ（`prompts.md` §2-1）

**M2. 「カメラ固定」「止まっている」と書いても動く／勝手に物が増える**（車が走り去って2台目が現れる、カメラが前進する）
- 原因：モデルが尺を埋める動きを足す。"tripod" と書くと三脚そのものが映ることもある
- 対処：`Static camera; the framing never changes.` と書き、生成後は必ずコマを並べて見る（4コマを横に並べた画像で、文字の出現・人体の破綻・余計な物を確認）

**M3. 生成映像の中の文字・看板・数字が崩れる**
- 原因：映像生成は文字を正しく描けない
- 対処：プロンプトで文字・ロゴ・看板を禁じ、テロップ・数字・名前はすべて HTML の層や字幕で重ねる

**M4. 高解像度・参照画像・終点フレームを使うと 400 で弾かれる**
- 原因：1080p・4k・参照画像・終点フレームは8秒しか受け付けない（2026-10 時点の Veo 3.1）。音声生成のパラメータを渡しても 400 になった
- 対処：その条件では8秒で頼む。API の受け付ける形は版ごとに変わるので、一次資料の例が通らなければ最小の要求から足していく

**M5. 生成物を後で取りに行ったら消えていた**
- 原因：生成物はサーバーに短期間（2日程度）しか残らない
- 対処：生成したら即ダウンロードする。再実行で続きから回せるよう「出力が既にあれば飛ばす」作りにする

**M6. 生成映像を HTML に埋め込むと、書き出しで止まった絵になる**
- 原因：キーフレームが疎で、コマ送り（seek）に失敗する
- 対処：埋め込む前に `ffmpeg -i in.mp4 -an -c:v libx264 -g 15 -pix_fmt yuv420p out.mp4` でキーフレームを密にする

**M7. 生成映像の人物を「顔の小さい遠景」と記録したら、表情の読める中景だった**
- 原因：見ずに推測で素材台帳を書いた
- 対処：人物・顔の大きさ・映り込みは、コマを見たとおりに記録する。使う区間を決める前に必ずコマを見る

**M8. 生成した施設・人物が実在のものと受け取られる**
- 原因：生成映像の上で「現場では」「当社の施設」と語った
- 対処：生成映像・生成人物を実在の施設・人物・記録映像として紹介しない。注記の要否は公開先の規約と法令に従う

## 生成画像・図

**I1. 部品を1つずつ頼むと、線の太さ・色・角度がばらばら**
- 原因：別々の生成では絵柄が固定されない
- 対処：「4列×3行・白地・文字なし」で1枚に12個描かせ、切り分ける（`prompts.md` §2-4）

**I2. 切り分けたら1個の品物が2つに割れた／皿の白まで透明になった**
- 原因：塊の検出だけで切ると、割れたガラスのような絵が別々の塊になる。白をすべて抜くと中の白も消える
- 対処：塊を「どのマスか」に割り当てて同じマスの塊をまとめる。透明にするのは画像の縁につながる白だけ

**I3. 既存の図に焼き込まれた数字・言い回しが原本と違っていた**
- 原因：画像の中の文字は機械の検査（字幕・JSON の検査）にかからない
- 対処：図を動画に使う前に、目で見て原本と照合する。使えない図の一覧を残す

**I4. 生成した装置の断面図の、中の光が炎に見えた**
- 原因：「中で何かが起きている」表現を光で描かせた
- 対処：別の工程（燃やす・爆発など）と誤解される絵は使わない。内部はコードで描いた図解で見せる

## ナレーション（TTS）と書き起こし

**V1. 同じ文を2回読んだ音声が返ってきた**（35秒のはずが61秒）
- 原因：TTS の不定な繰り返し。2文を1行にまとめた長い行で起きやすい
- 対処：台本は1行1文。生成後に全 wav の尺を並べて外れ値を探し、「聞こえた長さが台本の1.3倍超」は作り直す

**V2. 読み終えた後に間を置いて、原稿に無い文を勝手に足した**（禁止の数字を喋った例あり）
- 原因：TTS の暴走。書き起こし照合は後半を落とし、一致度0.98で合格にした
- 対処：「声のある長さ（0.25秒以上の間を除く）」が「字数÷その本の話速の中央値」より2.5秒以上長い文を作り直す。全体の長さ・文中の最長の無音で判定すると列挙文で誤検出する

**V3. 頭の数語を言い落としていた**（"Key point one:" "Q1." が消えた）
- 原因：一致度は文全体の似ている度合いなので、頭の数語が抜けても0.92〜0.93と高く出る
- 対処：書き起こしの頭2語・お尻2語を台本と機械で比べる。短い記号は言葉で書く（"Q1" → "Q one"）

**V4. 助詞・語尾の違いが一致度に出ない**（「〜も」→「〜は」、「とします」→「いたします」で合格）
- 原因：一致度の閾値は語尾の違いを拾えない
- 対処：仕上がった音声を丸ごと書き起こし、合格の行も「聞こえた」を全行読む。読み違いは読点を足して再合成（「完了と、します」）

**V5. 話し方の指示を本文として読み上げた**
- 原因：「落ち着いて読んで：本文」形式や、指示を本文に混ぜた
- 対処：台本形式（`### DIRECTOR'S NOTES` の下に指示、`#### TRANSCRIPT` の下に本文だけ）で渡す（`prompts.md` §2-6）

**V6. 文の途中で別の言語に切り替わった／台本の言語と違う文を勝手に訳して読んだ**
- 原因：多言語 TTS がまれに言語を取り違える。日本語版に混ざった英語の標語は訳されて読まれる
- 対処：全文を書き起こして照合し、NG の文だけ作り直す。読ませたくない語は台本に入れないか、その言語の文にして渡す

**V7. タイ語で西暦の年を仏暦に直して読んだ**
- 原因：TTS が年を現地の暦に変換した
- 対処：年の前に西暦であることを示す語（タイ語なら「ค.ศ.」）を付けて渡す。数字の読みは言語ごとに書き起こしで確かめる

**V8. 書き起こしが同音の漢字を取り違えて「不一致」になった**（制度→精度、炭素→探索）
- 原因：書き起こしモデルの誤り（声は正しい）
- 対処：一致度0.95未満は別のエンジンでも聞き、ひらがなで書き起こさせて読みを確かめる。最後は耳で

**V9. ローカルの書き起こしがモデルの読み込みで20分以上止まった**
- 原因：faster-whisper がモデル配布元への更新確認で待った
- 対処：キャッシュ済みなら `HF_HUB_OFFLINE=1` を付けて動かす

**V10. TTS の WAV の頭に雑音が乗り、長さもずれた**
- 原因：新しいモデルは WAV（ヘッダつき）で返すのに、旧モデル用のコードが生の PCM としてさらに WAV で包んだ
- 対処：返りの先頭が `RIFF` かを見て分ける

**V11. 2話者の合成が 400 で弾かれた**
- 原因：旧形式（1パートに「名前: 台詞」を並べる）を新しいモデルが受け付けない。SDK が新形式に未対応のこともある
- 対処：尺を確定させたい動画は1ターン＝1話者で合成して実測するほうが楽。2話者で頼むなら台詞1つ＝1パートに話者名を付ける

**V12. 指示に "slightly unhurried" と書いたら間延びした**
- 原因：話速の指示が強く効く（日本語で約5.3字/秒 → 約4.7字/秒）
- 対処：速さは「natural professional pace」程度にとどめ、尺の調整は台本の字数で行う。文ごとに4.3〜6.6字/秒くらいは揺れる前提で実測する

**V13. ナレーションを入れたら尺がほぼ倍になった**（105秒の無音版 → 3分14秒）
- 原因：画面の文字量と読み上げの量は違う
- 対処：尺を守りたいなら台本の段階で1場面1文に絞る。場面の尺＝語り出し1.0秒＋文の長さの合計＋文間0.5秒＋語り終わり1.2秒、で見積もる

## 音（BGM・ミックス・音量）

**A1. 生成曲の頭に約2秒の無音があり、1拍目がずれた**
- 原因：音楽生成モデルの出力の癖
- 対処：拍を解析し、最初の拍から切り出す

**A2. 「前奏なし・ブレイクなし」と書いても、前奏とブレイクが入った**
- 原因：指示が構成に効き切らない
- 対処：拍とエネルギーを解析してグルーヴの区間を選び、小節の頭から8小節単位で繰り返す。1単位の尺を8小節の整数倍にすると、つなぎ目で小節が飛ばない

**A3. 切り貼りした BGM で拍の解析が継ぎ目で途切れた**
- 原因：継ぎ目でテンポ推定が乱れる
- 対処：切り貼り前の元曲を解析し、その拍の時刻を写して使う

**A4. 完成品の音量が既存作より6dB小さかった**
- 原因：ffmpeg の `amix` は既定で入力数で割る
- 対処：`amix=inputs=2:normalize=0` を付け、BGM は `volume=` 側で下げる。納品前に `volumedetect`・`loudnorm` で測る

**A5. ラウドネスを −1.5 dBTP に合わせたのに、AAC にしたらピークが +0.9 dBFS にはみ出した**
- 原因：TTS の鋭い立ち上がりが、AAC への変換後に上振れする
- 対処：トゥルーピークは −2.0 で合わせ、AAC にした後の値で確かめる。音量は2パス loudnorm（1パス目で測り、2パス目で合わせる）

**A6. 1問ずつ音量をそろえたら、声のない頭が BGM だけで大きく聞こえた**
- 原因：短い区間ごとのラウドネス合わせは、声の無い区間で BGM を持ち上げる
- 対処：声のない区間は目標を下げる（例：全体 −16 LUFS に対し、頭は −20）

## 組み版（HTML・CSS・GSAP・HyperFrames）

**H1. カウントアップの数字とグラフが、書き出すと0のまま・空のまま**（機械QAは全部合格）
- 原因：`tl.render` を上書きして描く方式は書き出しで呼ばれない。tween の `onUpdate` もコマ送り（seek）では呼ばれないことがあり、終わった直後のコマで 0.9999 で止まる穴もある
- 対処：表示はプロキシのプロパティの setter で書き換える（GSAP がそのプロパティを動かせば必ず描かれる）か、時刻だけから値を計算して描く。書き出し前に静止画で数字が出ているかを目で見る

**H2. 要素が登場前から見えていて、時刻が来ると一瞬消えて入り直す**（1本で20回以上ちらつき、機械QAは全部合格）
- 原因：`immediateRender:false` の登場アニメの対象が、CSS で最初から見えていた
- 対処：遅れて登場する要素は CSS で最初から `opacity:0` にしておく。機械で拾うなら、文字領域の画素をコマごとに追い「表示中に落ちて戻る」を検出する

**H3. 1コマ目から出している要素が、0秒で一瞬消えた**
- 原因：最初に見せた要素を from＝透明の登場アニメで出し直していた。1秒1コマの一覧画像と静止画では写らなかった
- 対処：1コマ目から見せる要素に登場アニメを重ねない。表紙で見せた要素は CSS で見える状態から始め、後で引っ込める

**H4. 場面転換の頭0.1〜0.2秒が真っ黒になった**
- 原因：filter 未設定の要素に `to({filter:"brightness(.55)"})` と書くと、GSAP が brightness(0) から補間する
- 対処：`fromTo` で開始値（`brightness(1)`）を明示する。QA に `blackdetect` を入れる

**H5. 見出しだけが真っ黒、数字と欧文だけ明朝風の既定書体で出ていた**（2か月気づかなかった）
- 原因：部品化した場面の CSS がスコープ変換され、場面の最上位要素へのセレクタ（`#scene{color; font-family}`）が当たらなかった。継承に任せた要素だけが落ちた
- 対処：文字要素には色を明示する。書体は `*{font-family:...}` で全要素に直接当てる。最上位に効かせたい指定は JS で `style` に入れる

**H6. 文字送り（1文字ずつ出す）で、欧文が単語の途中で改行し、タイ文字の母音記号が外れた**
- 原因：`textContent` を1文字ずつ `inline-block` の span に割った
- 対処：テキストノードを辿り、`Intl.Segmenter` で「語」を改行しない箱にし、その中を書記素（grapheme）単位で span にする

**H7. 色の一括置換スクリプトで CSS と JS が壊れた**
- 原因：`#bad` `#fc1` のような ID セレクタが16進カラーと同じ形。`box-shadow` の正規表現が JS のテンプレート文字列を食った
- 対処：色はトークン（CSS 変数）で持ち、置換しない。置換したら `node --check` とセレクタの走査を必ず

**H8. 英語の見出しが枠から13pxはみ出した**
- 原因：フォント読み込みを待たずに大きさを決める文字幅の見積もりが、欧文で2割ほど甘い
- 対処：見積もりに余裕係数（0.8〜0.9）を掛けるか、事前検査を実際の描画幅で行う。欧文の版は必ず静止画で確認

**H9. 並んだ枠ごとに自動縮小したら、文字の大きさがばらばら**（26〜44px）
- 原因：枠ごとに「入る最大」を選んだ
- 対処：並ぶ枠（選択肢・段階ラベル・左右のセル）は最小値にそろえる。正解だけ大きい・右だけ大きいと意味を持ってしまう

**H10. 拍の位置に小数（4.5拍目）を使ったら、出来事が全部0秒に化けた**
- 原因：拍の配列を小数の添字で引いて undefined になった
- 対処：拍→秒の関数を補間に対応させる（`B(k)` を床と天井の線形補間で）

**H11. 人物を左右反転したら、アニメと衝突して位置がずれた**
- 原因：CSS の `transform: scaleX(-1)` と GSAP の transform が同じ要素を取り合った
- 対処：外側の箱を GSAP で動かし、内側の img だけを反転する

**H12. 変数の既定値に `'` を書いたら、変数宣言ごと壊れた**
- 原因：`data-composition-variables='[...]'` の属性がアポストロフィで閉じた
- 対処：既定値にアポストロフィを書かない（JSON 側に書くのは問題ない）

**H13. 書体に無い記号が別の細い書体で出た**（✉、下付きの ₂）
- 原因：使った書体にその字が無く、ブラウザが代わりの書体で描いた。目視の QA と既存の検査をすり抜けた
- 対処：JSON の全文字をフォントの cmap で検査する。無い記号は文字で書く（「メール：」「CO2」）

**H14. チャットの吹き出しが下端で切れた／話者アイコンの輪が切れた**
- 原因：入力中「…」の高さで窓を送ったので、吹き出しが出た瞬間に足りなくなった。輪は `overflow:hidden` の窓で切れた
- 対処：「…」の時点で吹き出しの高さぶん送る。窓だけ左右と上に10px広げ、中身を内側に寄せる

**H15. 長い書き出しが途中（3777/6900コマ）で落ちた**
- 原因：背景に 2.4MB の PNG を使い、ブラウザのメモリが尽きた
- 対処：背景写真は 1920×1080 の JPEG に落としてから使う。時間制限を上げるだけでは直らない

**H16. 書き出しの縮尺を 0.6667 倍にしたら、カードの縁がちらついた**
- 原因：半端な縮尺で、サブピクセルの位置がコマごとに揺れる
- 対処：下書きは 0.5、本番は 1.0 の区切りのよい倍率で

**H17. 地図の上の文字が、カメラ移動中に切れて見えた**
- 原因：移動中も札を出していた。カメラの「息」（ゆっくりした揺れ）を冒頭から入れたら、冒頭で札が切れ、最後と最初の差も大きくなった
- 対処：移動中は文字を隠し、引きの時だけの札は別の層に。息は冒頭の場面の後から始め、最後の1秒は止める（ループの継ぎ目がそろう）

**H18. 変数ファイルを渡した静止画が撮れない**
- 原因：静止画を撮るコマンドが変数ファイルを受け取らなかった（HyperFrames 0.8 系の snapshot）
- 対処：既定値を書き換えた複製で撮るか、書き出し後の一覧画像で確かめる。複製で撮ると欧文の記号（— ·）が化けることがあるので、欧文は本番の書き出しで見る

**H19. `file://` で開いたページでデータが読めない**
- 原因：`file://` では fetch が使えない
- 対処：データは `<script src="data.js">`（`window.DATA = {...}`）で読む。全コマの検査を file:// で回すならブラウザに `--allow-file-access-from-files`

**H20. 書き出しが壊れたブラウザで失敗した**
- 原因：道具に同梱のブラウザが壊れていた
- 対処：システムに入っている Chrome を明示して使う（HyperFrames は環境変数でブラウザのパスを指定できる）

**H21. 自前のコマ撮り（Playwright）で、タイムラインを動かす1行から先に進まなかった**
- 原因：`evaluate("t => tl.seek(t)")` が戻り値のタイムライン本体を返し、巨大で循環した物の直列化で止まった
- 対処：`t => { tl.seek(t, false); }` のように何も返さない。`false` を付けるとコールバックも走る

## 書き出し・ffmpeg

**R1. 前回の失敗が「成功」と判定された**（新しい声＋古い映像・尺も不一致）
- 原因：「無音版のファイルがあるか」で成否を見ていて、前回のファイルが残っていた
- 対処：書き出す前に対象の出力を消す。成否は終了コードと新しい更新時刻で見る。組み立ての尺＝完成動画の尺も照合する

**R2. 図の場面が空の枠のまま8秒止まっていた**（書き出しは成功扱い）
- 原因：書き出し中にローカルの配信が切れ、画像1枚の読み込みに失敗した
- 対処：ログの `media_load_failed`・`ERR_CONNECTION_RESET` を数え、1件でもあれば書き出しからやり直す。`freezedetect` で静止を拾う（黒コマ検査では出ない）

**R3. 2つの書き出しが同時に走り、古い HTML で書き出された**
- 原因：排他の錠が「同じ名前なら自分」と通していた
- 対処：錠のファイルに pid を書き、生存を確かめて待つ。メモリが少ない機械では書き出しは1本ずつ

**R4. 長い書き出しの途中で、一時フォルダごと消えて全部落ちた**
- 原因：OS の一時フォルダが何かに掃除された
- 対処：長い書き出しは一時フォルダ（`TEMP`/`TMP`、コマのキャッシュ）をプロジェクトの中に向ける

**R5. `-ss` で切った映像の1コマ目が無地の枠になった**（6本中5本）
- 原因：切った映像の最初のコマの時刻が0より後で、`overlay` に素通しされた
- 対処：`setpts=PTS-STARTPTS` で時刻を0に戻し、`tpad=start_mode=clone` で頭を埋める

**R6. 切り抜きの頭に、前の章の扉が一瞬映った**
- 原因：余白0.2秒ぶん前から読んだら、場面転換の途中だった
- 対処：場面転換が終わったコマから読み、頭はそのコマの止め絵にする。投稿先は先頭コマをサムネイルにすることが多い

**R7. 短い実写を止め絵で延ばしたら、ぶれた絵のまま7秒固まって見えた**
- 原因：素材が2〜2.7秒しかなく、最後のコマで止めた
- 対処：往復再生（端でゆっくり折り返す）か、減速して「ぶれていないコマ」に着ける。QA に `freezedetect`（1.5秒）

**R8. 色の印（bt709）が一部の項目にしか付かなかった**
- 原因：色空間だけ指定し、primaries・transfer を明示しなかった
- 対処：`setparams=colorspace=bt709:color_primaries=bt709:color_trc=bt709` と出力側の `-colorspace` などをすべて明示する

**R9. 新しい ffmpeg で `-filter_complex_script` が無いと言われた**
- 原因：ffmpeg 8 系の後の版でオプションが整理された
- 対処：`-/vf <ファイル>`（オプション名の前に `-/` でファイルから読む）を使う。drawtext の text の中の `:` と `,` は `\:` `\,` でエスケープ。drawtext は woff2 を読めないので TTF に戻して渡す

**R10. 10分の待機画面を HTML で書き出すと重すぎた**
- 原因：長尺を全コマ描画した
- 対処：48秒のループだけを書き出し、`-stream_loop -1 -t <秒>` でつないで、変わる部分（残り時間）だけ `drawtext` で描く

**R11. `concat -c copy` でつないだら、途中で映像が崩れた**
- 原因：1本だけ書き出し設定（fps・音声の周波数・チャンネル）が違った
- 対処：連結するクリップは全部同じ設定で書き出す（解像度・fps・H.264・AAC 48kHz ステレオ）

**R12. 「黒コマなし・静止なし」で合格したのに、確認画像が0枚だった**
- 原因：188文ぶんの `select` の式が長すぎて ffmpeg が起動できず、同じ実行の検出も走っていなかった（空の結果＝合格扱い）
- 対処：ffmpeg の出力から拾う検査は、まず終了コードを見て失敗なら不合格にする。長い式は分けて実行する

**R13. 波形の動画が重い**（1080p・4分で約48MB）
- 原因：波形が毎コマ変わり、圧縮が効かない
- 対処：1920×1080 の座標で描いて 1280×720 に縮め、GOP を長めに（4分で約27MB）

**R14. 背景のグラデーションに縞が出た**
- 原因：8bit の階調不足
- 対処：±1 のディザを掛ける（PNG は重くなる）

## 字幕・文字の検査

**S1. 画面に焼き込まれた文字の禁止語が、字幕の検査を素通りした**
- 原因：元動画の図のカードに書かれた言葉は、字幕ファイル（SRT）に無い
- 対処：組み立て HTML から要素ごとの文字と表示時間を出して検査する。HTML の無い元動画はコマを必ず目で見る

**S2. 欧文の字幕で、数と単位が別の札に割れた**（about 24｜hours、October｜26）
- 原因：SRT の cue のまま札にした／数字の前で改行した
- 対処：文ごとにつなぎ直し、切れ目に罰点（数の直後・冠詞や前置詞の直後）を付けて分け直す。英語の1行は42字程度が目安

**S3. 字幕を『』「」の中で割った**
- 原因：字数だけで改行した
- 対処：括弧の中では割らない規則を入れる

**S4. 1秒1コマの一覧画像と AI の見直しで、0.6秒だけ出る印を「出ていない」と誤検出した**
- 原因：短く出る要素がコマの間に落ちた
- 対処：見直しには1秒3コマで見せ、「短く出る要素は前後のコマも見てから欠落と判断」と指示する。一覧画像はコマの間に余白を入れる（隣と続いて図が二重に見え、不具合と誤認した）

## 中身・表現

**C1. 動画の棒グラフに、原本に無い比率が描かれていた**（「バランスよく」が 240:190:215 に）
- 原因：見た目を作るときに具体値を置いた
- 対処：棒の高さ・カウントアップの到達値・アイコンの数も「数字」。原本に無い比率は等量で描く

**C2. 訳したテロップで用語と「約」が削られた**（「約3時間」→ "only 3 hours"）
- 原因：日本語から直接「短く」と指示して訳させた
- 対処：人が書いた正本の訳を中継にし、訳後に逆翻訳して禁止語・「約」の脱落・誇張の追加を機械で拾う

**C3. 見出しが、一部の働きを全体の手柄のように読ませた**
- 原因：区間の字幕の言葉だけで作っても、組み合わせで意味が変わる
- 対処：機械の検査に通っても、人が見出しの意味を読む

**C4. 注記を縮めて、法令の対象を広げてしまった**（「◯◯等の焼却炉を禁止」→「焼却炉を禁止」）
- 原因：限定語を落とした。英訳で and を so にして因果を足した例も
- 対処：注記は原本の限定語を残す。因果の接続詞を足さない

**C5. 対談で、記事の中心主張を聞き手に言わせて筆者が退けた**
- 原因：反論役に主張を割り振った
- 対処：途中で離脱した人に逆の意味が伝わる。中心主張と但し書きは筆者が言う

**C6. クイズで、選択肢の長さから答えが分かった**
- 原因：正解だけ長く、理由つきだった
- 対処：3つの選択肢の長さと文字の大きさをそろえる。誤答も写真で切り取られたら誤解を生まない文言に

**C7. 会場で、通訳が訳し終わる前に正解が出た**
- 原因：5秒カウントだけの30秒版を、逐次通訳の入る会場で流した
- 対処：通訳が入るなら「考える時間」（約20秒・BGM を下げる）を入れる

**C8. 使い回した1文音声に「このケースでは」が残っていた**
- 原因：元の動画の文脈で書かれた文を、別の並びで使った
- 対処：前後を指す語（このケースでは・ここでも）を含む文は使わない。直前の文で意味が通る文は、その文とセットで使う

**C9. 凡例の色見本が逆の意味に読めた**
- 原因：ドーナツ・棒グラフにも色見本を付けた（「緑＝全量」に読める）
- 対処：色見本は1マスの意味があるグラフ（ピクトグラム・ワッフル）だけに付ける

**C10. 待機画面で「10:00 開始」と出して遅れて始めた**
- 原因：表示した時刻と運営がずれた
- 対処：表示した残り時間は約束。遅れるなら画面を止めて人が案内する

## 運用

- **成否は出力ファイルで見る**（更新時刻・サイズ・尺・映像と音声の両方・各場面の代表コマ）。プレビューの再生で判断しない
- **静止画で先に見る**。レンダ後の目視では0.1〜0.5秒の不具合を見落とす。動いている途中のコマも撮る
- **直しは1回1点**。直したら同じ秒の静止画を並べて比べる
- **テンプレートを直したら全話を書き出し直す**。合格した話だけ残すと版が混ざる
- **長い作業は途中で止まる前提で**。生成・合成は「出力があれば飛ばす」作りにし、再実行で続きから回す
